# M3 Acceptance Record — Worktree and Git Recovery

- Status: Complete
- Accepted: 2026-07-26
- Scope: Repository registration, pinned commits, isolated worktrees, Git
  artifacts, controlled commits, mutation coordination, cleanup, and recovery

M3 introduces Git as an infrastructure effect without moving observations into
the deterministic runtime. The adapter implements ADR-0007: worktrees have
deterministic run identity, shared repository mutations use cross-instance
filesystem locks, and commits use reproducible inputs plus compare-and-swap
recovery.

## Recovery boundary proven

```text
registered canonical repository + pinned starting commit
                            ↓
           deterministic run worktree identity
                            ↓
          coordinated and observed Git mutation
                            ↓
        atomic metadata or checksum-bearing artifact
                            ↓
       retry reconciles exact worktree/commit identity
```

Worktree creation may be retried after Git succeeds but before metadata is
written. The adapter verifies the common Git directory and proves that the
pinned starting commit remains in the recovered worktree history before
recording the metadata.

Controlled commit inputs fix the parent, tree, message, author, committer, and
timestamp. The resulting commit object can therefore be reconstructed after an
interruption. `HEAD` advances only from the expected parent; an already-matching
commit is returned as recovered, while any other tree or HEAD is a typed
conflict.

## Compatibility and performance

- This milestone adds `@kouro/sandbox-worktree`; it does not change the M1 event
  model or M2 SQLite schema.
- Repository locks are filesystem records keyed by the canonical common Git
  directory. Live owners are never reclaimed; dead owners can be reconciled.
- Git commands are intentionally sequential per repository. Worktree contents
  remain isolated and different repositories can proceed independently.
- Worktrees are an isolation mechanism, not a security sandbox.
- Harness execution, artifact persistence in SQLite, and API composition remain
  deferred to later milestones.
