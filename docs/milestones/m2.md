## Durable boundary proven

```text
pinned compiled workflow + ordered SQLite events
                       ↓
              pure M1 projection
                       ↓
            deterministic next intent
                       ↓
       idempotent transactional event commit
                       ↓
        event history + query projections
```

The event insert, idempotency record, run state, invocation projection, attempt
projection, and approval projection update in one SQLite transaction.

## Recovery behavior

When the coordinator restarts, it records any active attempt as interrupted.
The pure scheduler then applies the operation's snapshotted policy. M2 executes
the `replay_safe` command path. Verification, reconciliation, resumable
sessions, worktrees, Git effects, and harness-specific recovery remain bound to
the later adapters that can make those observations safely.

## Compatibility and performance

- This milestone introduces the first SQLite schema; no migration from an
  earlier durable schema is required.
- Projections are rebuilt from the projected run state on each event. This is
  intentionally the simplest correct implementation for the sequential MVP.
  Incremental projection updates are deferred until representative profiling
  demonstrates a need.
- Command stdout and stderr are not placed in the event stream. Durable command
  log artifacts are deferred until the atomic artifact writer is implemented.
- SQLite uses foreign keys and WAL mode. Event sequence and idempotency
  uniqueness are also enforced by database keys.
