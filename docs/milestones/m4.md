# M4 Acceptance Record — Harness-independent Agent Execution

- Status: Complete
- Accepted: 2026-07-26
- Scope: Normalized harness execution, provider registry, structured output,
  durable artifacts, Claude Code, Codex, OpenCode, and Pi adapters, per-node
  routing, fallback, and resume

M4 introduces agent execution without changing the provider-neutral ADW
contract. Run configuration snapshots the ordered harness policy, and the
application resolves compiled roles, prompts, schemas, and capabilities through
the ports defined by ADR-0008.

## Execution boundary proven

```text
provider-neutral compiled agent node
                  +
snapshotted ordered harness policy
                  ↓
       normalized application port
                  ↓
 Claude Code | Codex | OpenCode | Pi | fake
                  ↓
independent schema validation + atomic artifacts
                  ↓
       ordered durable run events
```

The selected harness ID is part of the attempt history. A known failure records
typed data before the next configured harness can run. The reducer rejects a
fallback not authorized by the snapshotted policy, so a fallback cannot alter
the graph or bypass attempt identity.

Resume tokens become durable when an adapter returns them. Once recorded, an
interruption resumes the same harness session and attempt. If the process stops
before a token is recorded, the existing `resume_supported` policy requires
reconciliation rather than silently starting a new session.

## Compatibility and performance

- M4 adds new append-only event variants and additive SQLite artifact
  projections. Existing M1–M3 histories remain valid.
- Harness processes are sequential in the current coordinator. Bounded
  concurrency remains deferred.
- Artifact publication uses complete temporary files and atomic no-overwrite
  links. An identical retry is accepted; different content at the same durable
  identity is a typed artifact failure.
- The in-process schema validator implements the JSON Schema keywords required
  by compiled Kouro schemas: types, object properties, required and additional
  properties, arrays, length bounds, enum, const, and composition.
- Live authenticated harness execution is environment-dependent; acceptance
  uses each real adapter contract with scripted process output.
