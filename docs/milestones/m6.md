# M6 Acceptance Record — Observable Elysia and web MVP

- Status: Complete
- Accepted: 2026-07-26
- Scope: Typed application queries, in-process Elysia transport, Eden client,
  reconnectable durable-event replay, and a read-only execution dashboard

M6 adds the observable application boundary described by ADR-0010. It does not
change scheduler, reducer, transition, or recovery semantics.

## Acceptance evidence

| Criterion | Evidence |
| --- | --- |
| API tests run without opening a network port | `api-web-mvp.test.ts` uses `app.handle(Request)` |
| Domain and runtime packages do not import Elysia | `api-web-mvp.test.ts` boundary assertion |
| A run can be understood without reading SQLite | Run details expose status, workflow graph, invocations, attempts, events, approvals, and artifacts |
| Approval can be completed through the web UI | Typed approval endpoint and dashboard approval control |
| Reconnecting clients replay after their last sequence | `Last-Event-ID` integration coverage |

## Delivered boundary

```text
React dashboard / Eden client
             ↓
       Elysia handlers
             ↓
 application read and approval use cases
             ↓
 coordinator and declared query/content ports
             ↓
 SQLite history and checksum-verified artifacts
```

The dashboard includes a run list, read-only React Flow graph, node and attempt
details, durable event log, artifact and diff viewer, and approval controls.

## Compatibility and performance

- SQLite adds only an ordered run-list query; no schema migration is required.
- All observable state remains derived from the compiled bundle and durable
  event history.
- Event replay is cursor-bounded by durable sequence. Live clients reconnect
  through standard SSE behavior.
- The MVP intentionally keeps API, coordinator, and worker composition in one
  process. Distributed workers and visual workflow editing remain deferred.
