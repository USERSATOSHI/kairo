# T2 — Kairo run integration

- Status: Accepted
- Date: 2026-07-26

## Delivered

- immutable ticket snapshots captured before run launch;
- durable ticket-to-run links with multiple-run history;
- application port for invoking the existing run-start boundary;
- one-active-implementation-run policy with explicit parallel-variant opt-in;
- pure active-run ticket-change policy decisions;
- execution-board columns derived from Kairo run projections;
- SQLite snapshot and link persistence;
- Kairo run-query adapter for the ticket application layer.

## Invariants

- runs consume snapshots, never mutable ticket rows;
- ticket planning status is unchanged by derived execution columns;
- board movement cannot append runtime events;
- active-ticket changes produce application commands only;
- historical ticket runs and snapshots remain queryable.
