# M7 Acceptance Record — Runnable local MVP and operator CLI

- Status: Complete
- Accepted: 2026-07-26
- Scope: Packaged ADW execution, local worker/host composition, operator CLI,
  durable lifecycle controls, restart recovery, final Git delivery, API, and
  production web serving

M7 composes the M1–M6 boundaries into one runnable local product. ADR-0011
defines durable lifecycle controls, ADR-0012 defines single-process worker
ownership, and ADR-0013 defines the executable composition boundary.

## Acceptance evidence

| Criterion | Evidence |
| --- | --- |
| Fresh checkout exposes stable help and version | `local-mvp-cli.test.ts` launches the binary entrypoint as a real subprocess |
| Built-in feature workflow reaches a named merge-ready branch | `local-mvp-cli.test.ts` compiles the packaged ADW and verifies the Git ref |
| CLI/application approvals preserve one durable run | `local-mvp-cli.test.ts` crosses both durable gates around a process restart |
| Restart does not duplicate completed work or Git effects | SQLite reopen and idempotent controlled delivery in `local-mvp-cli.test.ts` |
| Pause and interrupt are distinct durable operations | lifecycle event assertions in `local-mvp-cli.test.ts` |
| Retry obeys recovery policy | replay-safe retry assertion in `local-mvp-cli.test.ts` |
| Skip is workflow eligible and checksum/HEAD bound | bound skip-event assertion in `local-mvp-cli.test.ts` |
| CLI and HTTP expose one state | final run is read through the in-process Elysia boundary |
| Configuration is snapshotted | run configuration records ADW, permissions, harnesses, repository, worktree, branch, and operator |
| No real provider is required for end-to-end tests | `ScriptedFakeHarness` drives the complete workflow |

## Delivered boundary

```text
kairo CLI / production web / typed HTTP
                  ↓
        LocalKairoHost application
                  ↓
 SQLite + LocalWorker + per-run coordinator
                  ↓
 packaged ADW + harnesses + artifacts + worktree/Git
```

The worker advances only durable runs and stops at approval, pause, terminal,
or reconciliation boundaries. Final status and binary diff are published before
completion, then a controlled commit is exposed through `kairo/<run-id>` without
merging or deploying it.

## Compatibility and performance

- Lifecycle and skip events are additive append-only event variants.
- `skipOutcome` is optional; existing workflows remain unskippable.
- SQLite schema is unchanged.
- Worker execution is deliberately sequential and bounded; distributed leases
  and parallel scheduling remain post-MVP.
