# T4 — Forgejo Issues

- Status: Accepted
- Date: 2026-07-26

## Delivered

- configurable Forgejo instance, repository, project, and credential inputs;
- normalized instance URLs and strict binding ownership checks;
- Forgejo version detection through the v1 API;
- per-instance OpenAPI capability discovery with explicit configuration
  overrides;
- durable non-secret instance version and capability metadata;
- issue import, read, paginated list, create, and update;
- comments, labels, assignees, milestones, close, and reopen;
- provider-neutral typed failures and explicit stale-revision rejection;
- HMAC-SHA256 Forgejo webhook validation and issue-payload normalization;
- polling reconciliation through the existing provider-neutral ticket sync
  service when webhooks are unavailable.

## Invariants

- Forgejo instance differences remain inside the provider adapter;
- a binding cannot be used through a different instance or repository
  connection;
- credentials and webhook secrets are constructor inputs and are never
  persisted;
- only non-secret instance metadata and capabilities are durable;
- advertised capabilities can be restricted by instance configuration;
- labels and milestones are resolved to Forgejo identifiers before writes;
- provider failures never alter Kairo run results;
- webhook and polling inputs use the same durable reconciliation path.
