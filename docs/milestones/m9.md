# M9 — Review-bound delivery and pull requests

- Status: Complete
- Accepted: 2026-07-28

M9 replaces implicit final Git finalization with an explicit `delivery_review`
node. The worker publishes an exact prepared tree, diff, and editable metadata
proposal before approval. Approval creates only that tree and records the local
commit and `kouro/<run-id>` branch.

The launching TTY remains attached across operator boundaries, `kouro attach`
reconnects later, and non-TTY runs return structured pending-action state.
CLI and web decisions use the same durable approval and optimistic event
sequence. Delivery review supports two context-preserving change requests,
terminal failure, metadata editing, and diff inspection.

GitHub and Forgejo publication use a provider-neutral port and separate
adapters. Push and pull-request creation reconcile existing remote state before
creating anything. Publication failure remains retryable and cannot turn a
locally successful run into a failed run.

Validation evidence:

- delivery authoring, compiler, reducer, scheduling, and metadata unit tests;
- local-host restart, exact-tree commit, API approval, and worktree integration
  tests;
- provider-neutral verify-then-create tests;
- full format, lint, typecheck, unit, simulation, integration, and web build
  gates.
